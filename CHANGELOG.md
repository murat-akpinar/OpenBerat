### 🚀 Features

- The design, the decisions, and the container skeleton ([65ed744](https://github.com/murat-akpinar/OpenBerat/commit/65ed74439e5e57e607b7aae4433474f7b3037956)) — OpenBerat is an identity-aware proxy: Keycloak federates to Active Directory, and a user reaches only the applications their AD group membership allows, through a portal and without a VPN. This commit is the whole design and none of the runtime — eighteen ADRs, the target architecture with its request path and ports, the requirements and the roadmap, alongside the per-container directories whose Dockerfiles are still commented stubs. Phase 1 is a lab that verifies the architecture against a real directory before a line of code is written.
- The kill switch gets an index, and the documents stop contradicting each other ([3dc2f33](https://github.com/murat-akpinar/OpenBerat/commit/3dc2f33fa854d8052600db738d3640a753e520ae)) — The five-second kill switch was unimplementable as written. oauth2-proxy keys its Redis sessions by ticket rather than by user, so nothing in the design could find the session belonging to a `sub` — the second half of the two-place revocation was a sentence, not a mechanism, and without it the switch degrades to `cookie_refresh`, five minutes. ADR-0019 gives the backend a `sub → session` index, written on the cache-miss path where it already holds the cookie, and fixes the revocation order at four steps. The claim it rests on is not verified: Phase 1 gains VERIFY (4), and if the session key turns out not to be derivable from the cookie, the fallback and the revision of ADR-0016 are written down rather than discovered later.
- *(lab)* Wildcard certificate — :443 enabled, INSTALL.md first draft ([467b877](https://github.com/murat-akpinar/OpenBerat/commit/467b877e1ed1b20e004de7ae817d75aeb3ee668b)) — The first Phase 1 item. A self-signed wildcard for *.apps.example.local is generated on the lab host (certs/ stays gitignored), the :443 server block is enabled, and INSTALL.md starts with the steps exactly as executed — prerequisites, certificate, name resolution, .env, start. Verified live: the presented certificate carries the SAN wildcard and validates without -k, HTTP/2 200 on two wildcard hosts, :80 → 301. Which CA signs the production certificate stays open (docs/06).
- *(lab)* The login chain works end to end — VERIFY (1) answered ([3a87730](https://github.com/murat-akpinar/OpenBerat/commit/3a877300886a089f734a9efc887d831e10ba41d9)) — The realm export, the oauth2-proxy configuration and the portal + Keycloak server blocks, brought up together on the lab host until a browser login completes and the portal serves the user their page.
- *(lab)* The double hop costs 126 microseconds ([f1afcad](https://github.com/murat-akpinar/OpenBerat/commit/f1afcadbe771d88ccfc02bd25e4ed09338181f63)) — ADR-0002 spends an extra internal hop on every request: nginx cannot chain a second auth_request, so the chain runs inside the backend and the PDP calls oauth2-proxy rather than nginx calling it directly. That decision has been carrying an unmeasured bill since the design. It is 126 microseconds.
- *(lab)* The websocket ran for eight minutes after its group was gone ([c3e9175](https://github.com/murat-akpinar/OpenBerat/commit/c3e9175576a998e77afdf9815ac1b4caa969b93e)) — An active connection is authorised once, at the upgrade, and never again. Measured: one echo connection carrying a frame a second, plus an HTTP poller on the same cookie and the same authz target. The HTTP path was cut 292 s after labuser lost the group, at the cookie_refresh boundary; the connection carried 500 exchanges over 499 s, 489 s of them after the group was gone, and returned every frame in ~0.2 ms. This is ADR-0016's exclusion measured rather than asserted.
- *(migrations)* Initial schema for application, entitlement and audit ([f748b14](https://github.com/murat-akpinar/OpenBerat/commit/f748b14ee523ca4bbea19dc94f3d2bb7089763bc)) — The three v1 tables, applied and checked against a real Postgres 17 by `backend/tests/schema.rs`. `audit_event` is partitioned by month with the PK on `(id, ts)` and a DEFAULT partition, and starts with the summary columns it can never gain later.
- *(store)* Apply migrations at startup, exit if one fails ([398c869](https://github.com/murat-akpinar/OpenBerat/commit/398c869b2af48252cca9485c73bfaf1fec2621fb))
- *(policy)* The decision function and its URI normalisation ([e4d4a57](https://github.com/murat-akpinar/OpenBerat/commit/e4d4a5700129dfe1fba7c67d6225a50b5babc10a)) — `decide` takes the raw `X-Original-URI` and normalises it inside itself rather than trusting a caller to have done it. The one hole in this design is somebody matching the raw string — `/%61dmin/`, `//admin/`, `/x/../admin/` and `/ADMIN/` all walk past a `/admin/*` deny rule while the upstream serves the same page — and a signature that cannot express that closes it. Fourteen tests, every row of the `docs/05` normalisation table among them; each guard was removed in turn to see the test that covers it fail.

### 🐛 Bug Fixes

- Thirteen design errors found before any code depended on them ([9e85ecf](https://github.com/murat-akpinar/OpenBerat/commit/9e85ecf3fc2fd41adcd3d41c00552254cc7e8495)) — The pre-code review found thirteen design errors; fixing them today is a text edit, fixing them in Phase 3 would have been migrations. The worst three: a flat docker network let a compromised upstream reach the backend, Redis and Postgres directly (split into edge/core, nginx the only member of both); the session cookie was forwarded verbatim to every upstream (now stripped before proxying, ADR-0015 corrected); and logout's third step had no caller — nothing ever dropped the cache, so a replayed cookie outlived logout by a TTL (now POST /api/logout, run in kill-switch order before the sign-out redirect).
- Six more design gaps found before any code depends on them ([382f94c](https://github.com/murat-akpinar/OpenBerat/commit/382f94c71d3c762fc794552d493996f75d3388f1)) — A cache entry could leave the cache by four roads — TTL, LRU eviction, logout, kill switch — and only TTL expiry flushed its audit counters: the kill switch would have erased the audit trail of the very user under incident response. The /decide response contract never said how nginx learns the identity it rewrites upstream (response headers, the only channel auth_request offers). Admin mutations and kill switch use had no stated audit at all — now F-14, the structured log stream in v1. A failed sub->session index write silently produced unkillable sessions — now a fail-closed DENY, written before the ALLOW it enables. Keycloak's public hostname was never pinned — auth.apps.<domain>, inside the wildcard, session cookie stripped, name reserved in the ADR-0011 generator. And VERIFY 4 never asked whether the Redis key survives cookie_refresh.
- The realm export carries no secrets, and the portal auth path is pinned ([01e1596](https://github.com/murat-akpinar/OpenBerat/commit/01e159693d7fab8b78e37b17c30dbfde45388148)) — The repository is public and keycloak/README.md said a UI change is re-exported and committed — which would have committed the OIDC client secret with it. The export is now scrubbed by rule; how the real secret is injected at import (env substitution or a post-import step) is a Phase 1 verification. And the portal host's auth mechanism was never pinned: its auth_request targets /oauth2/auth directly, not /decide — authentication without policy — which also means a portal-only user never enters the kill-switch index, a consequence now stated where the decision is.
- *(nginx)* A user in many groups was locked out by the 4k header buffer ([072e6a5](https://github.com/murat-akpinar/OpenBerat/commit/072e6a5c9e5307035bb303d2c8944783bc6a1947)) — The cookie size problem the Redis session store was chosen to solve is gone — the session cookie stays 192 bytes from 1 group to 800, never chunked — but the 4 KB limit moved rather than disappeared. Every group name comes back comma-joined in one X-Auth-Request-Groups, nginx reads a response header block into a single proxy_buffer_size buffer (one page), and auth_request maps the resulting 502 onto a 500 for the client. Ramped on the lab: clean at 100 groups, locked out between 100 and 200, with a passing nginx -t and no warning in any log — a total lockout of exactly the accounts an enterprise has most of.
- *(nginx)* The login redirect lost half of the query string ([6a48b02](https://github.com/murat-akpinar/OpenBerat/commit/6a48b02b92769ee2e8bb4708a77778a380ca37cb)) — The return address went into `?rd=$scheme://$host$request_uri`, and nginx cannot percent-encode it, so the client's own `&` started a new parameter of /oauth2/start. Measured: `/index.html?a=1&b=2` came back as `/index.html?a=1` — a 200, the right page, and everything after the first `&` silently gone. A deep link into a protected application would suffer that after any session expiry. An injected `rd` arrived as a second one; not exploitable (the first wins, `whitelist_domains` sits behind it), but the client was writing into the query string of a request it never made.
- .env.example was missing three variables the stack cannot start without ([b15e6b3](https://github.com/murat-akpinar/OpenBerat/commit/b15e6b37f353f562158658553a4cc3e998e1e6d8)) — docker-compose.yml reads eight variables and .env.example offered five. A fresh clone copying it to .env and running `docker compose up` gets an empty OAUTH2_PROXY_COOKIE_SECRET (oauth2-proxy refuses to start), an empty OPENBERAT_CLIENT_SECRET (the OIDC client secret Keycloak resolves at import) and an empty LAB_USER_PASSWORD — compose substitutes an empty string for an unset variable rather than complaining, so the first symptom is a container that will not come up.
- *(install)* Three steps only worked on the host that wrote them ([4d9e2f2](https://github.com/murat-akpinar/OpenBerat/commit/4d9e2f254ae97246839113c8d93e89184b79de7b)) — INSTALL.md said every step had been executed on the lab host, and they had been — on a host that already had the directory, the secret and the password the document tells you to create. Replaying §1-§4 from a clean checkout, with nothing but the file, broke three times before the first login.
- *(lab)* Samba needs a kernel the lab host does not have ([ae872d2](https://github.com/murat-akpinar/OpenBerat/commit/ae872d22a3ea1c5c8241fc3b7a4a1b313198fb6b)) — Bringing samba-ad up for the first time failed twice. The first one was ours: `hostname: ad` with `AD_DOMAIN=ad.example.local` gives the DC and the domain the same NetBIOS name and Samba refuses to provision. It is now dc01 in example.local — the pair docs/03 already documents, which also makes its example DNs literally correct.

- *(verify)* Nginx skips the access phase in a subrequest — VERIFY (3) answered ([017849b](https://github.com/murat-akpinar/OpenBerat/commit/017849b5dbf42c7b4f22f3b13457d7df24532dd7)) — Both halves measured on the lab. An `auth_request` subrequest cannot itself trigger `auth_request` — the whole access phase is skipped, `deny all` in the same position is ignored too — so the chain stays inside the backend and ADR-0002 is unchanged; `internal;` still guards `/decide`, but an `allow`/`deny` beside it would test clean and constrain nothing. And the subrequest inherits the main request's headers verbatim: every name the `/decide` include does not overwrite reaches the PDP exactly as the client wrote it, so the include now clears the `X-Auth-*` family as well. `docs/05`'s attack table only ever covered the upstream direction.
- *(verify)* The Redis session key derives from the cookie — VERIFY (4) answered ([aaccee0](https://github.com/murat-akpinar/OpenBerat/commit/aaccee02013147d17f02f170b14436fcb66654a6)) — Both halves measured on the lab; ADR-0019 holds and with it ADR-0016's 5 s kill-switch target. The key oauth2-proxy stores the session under in Redis is recoverable from the raw cookie the backend already holds on every cache miss: drop the `|ts|hmac` signature, base64-decode the `v2.<handle>.<secret>` ticket, base64url-decode the handle, and out comes the live `_oauth2_proxy-<hex>` key — matched exactly against a labuser login. No oauth2-proxy secret is needed; the handle rides in the cookie in the clear.
