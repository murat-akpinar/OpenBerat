### 🚀 Features

- The design, the decisions, and the container skeleton ([65ed744](https://github.com/murat-akpinar/OpenBerat/commit/65ed74439e5e57e607b7aae4433474f7b3037956)) — OpenBerat is an identity-aware proxy: Keycloak federates to Active Directory, and a user reaches only the applications their AD group membership allows, through a portal and without a VPN. This commit is the whole design and none of the runtime — eighteen ADRs, the target architecture with its request path and ports, the requirements and the roadmap, alongside the per-container directories whose Dockerfiles are still commented stubs. Phase 1 is a lab that verifies the architecture against a real directory before a line of code is written.
- The kill switch gets an index, and the documents stop contradicting each other ([3dc2f33](https://github.com/murat-akpinar/OpenBerat/commit/3dc2f33fa854d8052600db738d3640a753e520ae)) — The five-second kill switch was unimplementable as written. oauth2-proxy keys its Redis sessions by ticket rather than by user, so nothing in the design could find the session belonging to a `sub` — the second half of the two-place revocation was a sentence, not a mechanism, and without it the switch degrades to `cookie_refresh`, five minutes. ADR-0019 gives the backend a `sub → session` index, written on the cache-miss path where it already holds the cookie, and fixes the revocation order at four steps. The claim it rests on is not verified: Phase 1 gains VERIFY (4), and if the session key turns out not to be derivable from the cookie, the fallback and the revision of ADR-0016 are written down rather than discovered later.

### 🐛 Bug Fixes

- Thirteen design errors found before any code depended on them ([9e85ecf](https://github.com/murat-akpinar/OpenBerat/commit/9e85ecf3fc2fd41adcd3d41c00552254cc7e8495)) — The pre-code review found thirteen design errors; fixing them today is a text edit, fixing them in Phase 3 would have been migrations. The worst three: a flat docker network let a compromised upstream reach the backend, Redis and Postgres directly (split into edge/core, nginx the only member of both); the session cookie was forwarded verbatim to every upstream (now stripped before proxying, ADR-0015 corrected); and logout's third step had no caller — nothing ever dropped the cache, so a replayed cookie outlived logout by a TTL (now POST /api/logout, run in kill-switch order before the sign-out redirect).
- Six more design gaps found before any code depends on them ([382f94c](https://github.com/murat-akpinar/OpenBerat/commit/382f94c71d3c762fc794552d493996f75d3388f1)) — A cache entry could leave the cache by four roads — TTL, LRU eviction, logout, kill switch — and only TTL expiry flushed its audit counters: the kill switch would have erased the audit trail of the very user under incident response. The /decide response contract never said how nginx learns the identity it rewrites upstream (response headers, the only channel auth_request offers). Admin mutations and kill switch use had no stated audit at all — now F-14, the structured log stream in v1. A failed sub->session index write silently produced unkillable sessions — now a fail-closed DENY, written before the ALLOW it enables. Keycloak's public hostname was never pinned — auth.apps.<domain>, inside the wildcard, session cookie stripped, name reserved in the ADR-0011 generator. And VERIFY 4 never asked whether the Redis key survives cookie_refresh.
- The realm export carries no secrets, and the portal auth path is pinned ([01e1596](https://github.com/murat-akpinar/OpenBerat/commit/01e159693d7fab8b78e37b17c30dbfde45388148)) — The repository is public and keycloak/README.md said a UI change is re-exported and committed — which would have committed the OIDC client secret with it. The export is now scrubbed by rule; how the real secret is injected at import (env substitution or a post-import step) is a Phase 1 verification. And the portal host's auth mechanism was never pinned: its auth_request targets /oauth2/auth directly, not /decide — authentication without policy — which also means a portal-only user never enters the kill-switch index, a consequence now stated where the decision is.
