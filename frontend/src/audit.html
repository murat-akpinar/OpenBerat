A row is a session key, not a user who is active — and not always a credential that still works. The three read alike and only one of them is true. A session stops working after 30 minutes idle or 10 hours in total, but its key stays in Redis until somebody uses the cookie and finds it dead, so a closed laptop or a script that logged in and exited is counted here for a while after it can no longer get in. Counting keys is still the right direction for a page about revocation: what matters is what would let somebody in, not who happens to be typing.

Read out of the index the kill switch uses, so it sees the user who signed in and opened nothing — the history tab never would. What it cannot tell you is when a session started or where from: the index holds a subject and its session keys, and nothing else. To end one, run the kill switch (INSTALL.md §6); nothing on this page writes.

One row is a summary, not a request: a user hitting the same application with the same outcome inside one cache entry arrives here as a single row with a count. The verdict below is policy::decide's own — the same function the proxy runs — over the entitlement rows it would walk. It reads the table, while the proxy may still be answering from a cached decision, so for up to 30 seconds after a rule change this page is right and the live URL is stale.

A row here is a real nginx server block: saving one re-renders the generated configuration and stages it for the proxy to test and load (ADR-0011), and the result of that staging is reported on every save. A row the proxy has not taken up yet is reachable by nobody, which is the right direction to fail in but not one to be surprised by.

The slug and the external hostname cannot be changed after creation. Both are written into the generated block and into every audit row that names this application, so renaming one would silently reassign history. Delete and recreate instead, knowing what the delete takes with it.

One row is one rule. A deny that matches beats any allow, and a user no rule matches is denied — an absent rule is a decision, not a gap. The path is a subtree: /admin/* covers /admin/ and everything under it, and a pattern without the trailing * is refused rather than quietly narrowed (ADR-0029). Leave it empty for the whole application.

An application of every application is a wildcard that applies to every application defined now and every one defined later (docs/05, rule 4). It is logged as its own action for that reason. Use Explain before telling a user a rule works.
